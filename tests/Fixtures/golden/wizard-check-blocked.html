Something here blocks every client

Not one client will connect until this is fixed, whatever it is and however it is configured. Each failure below states the change that fixes it.

  • Abilities APIAvailable. Abilities can be registered and published as tools.
  • MCP AdapterActive. It turns the registered abilities into MCP tools and serves the transport.
  • Pretty permalinksDisabled. The REST API still answers through its ?rest_route= form, which no client will guess, and the discovery documents would advertise URLs that 404. Set any structure but "Plain" under https://example.test/wp-admin/options-permalink.php.
  • HTTPSThe site is served over TLS.
  • Required capabilityYou hold edit_posts. Granted by: Administrator.
  • Discovery documentsBoth documents answer with JSON at their well-known paths, which is where RFC 8414 and RFC 9728 pin them.
  • Published tools5 ability groups enabled. Abilities register on demand, so the live count comes from the endpoint rather than from this screen.

The discovery documents are the link that fails most often, and the only one that leaves no trace: a web server blocking /.well-known/ refuses the request before PHP is reached. The answer is cached for five minutes, so change the server, then ask again.
